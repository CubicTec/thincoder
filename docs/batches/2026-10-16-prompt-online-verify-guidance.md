## 机制设计（V1 —— 单源本节）

新增一个 `### 子节`（住 `## 工具观` 内、紧邻「搜索工具优先级」节之后），逐字如下（**改后文本**）：

```text
### 何时必须联网查证
**凭训练记忆答版本 / API / 协议行为 = 猜**——记忆有截止日、会记错；下这类结论前先查证。
**必须查的情形**：① **时效**——版本号 / 发布状态 / 「最新 · 现行」的库 · 工具 · 服务行为 / 额度 · 限额；② **精确**——公开 API · SDK · 协议的签名 · 参数 · 默认值 · 错误码 · 端点，配置键名与取值范围；③ **否定式断言**——「某特性不存在」「某行为不是这样」——记忆里的否定最不可靠；④ **与实证冲突**——记忆和眼前代码 / 实测读数矛盾时，以实测为准、联网取第三方佐证。
**查到什么算够**：拿到**一手源**（官方文档 / 官方仓库 / 规范）的原文句或代码片段，能指到具体页面 / 文件。二手转述（博客 / 问答 / 聚合站）只算线索——回溯到一手源或实测证实才算查到；**没有一手源 ⇒ 明说「未证实」**，不靠语气装肯定。
**查不到怎么办**：被墙 / 不可达 ⇒ 换镜像路径或换源再试一两轮；仍无一手源 ⇒ 结论写明**「查过、无一手源」**并标 `unverified`——绝不拿记忆补空、绝不编造来源。
**边界**：查证 = **取事实**，不是**照行业清单抄一遍**——判据以证据为准，不是「搜了就算查过」。**常识无需查**（语言语法 / 通用算法 / 公知常识——查 = 浪费回合）。**不写死工具**：用哪款搜索 / 抓取工具现选，受网络可达性约束（境外站点可能访问不了；必要时把中文先译成英文再查）——拿到事实即可，路径随环境。
```

**三件对应**：必须查的情形（第二行）∥ 查到什么算够（第三行）∥ 查不到怎么办（第四行）。第五行 = 边界（用户五条边界里的「常识无需查」+「查事实 ≠ 抄清单」+「联网前提 / 不写死工具 / 翻译问题」）。

**形态约束（逐条可核）**：

- **禁裸口号**——每件都带可操作形（情形给四类触发 · 算够给判据（一手源 + 原文/片段）· 查不到给三步（换路径 → 换源 → 标未证实））。
- **禁文档引证**——全文零 `.md` 档名、零 `§` 号（机判式 `J1/J2/J3` 零命中）。
- **零重复**——不重写「搜索工具优先级」节（工具优先级 / 抓取法单源不动）；本节只答「何时查、够没够、查不到」。
- **零 `##` 块计数连带**——新内容为 `###` 子节。
