# 桌面需求 · 设置与首启（SETTINGS）

> **卷**：桌面端需求分卷之「设置与首启」——**D7 ∥ D8 ∥ D9 ∥ D11 ∥ D16 ∥ D37 ∥ D39**（7 条）。
> **总览 ∥ D 表索引**：`docs/desktop/requirements/PROJECT.md`（D1–D42 全表查卷口；模块目标 / 定位 / 界面形态 / 边界 / 非功能 / 验收 / 依赖）。**同族设计档**：`docs/desktop/design/SETTINGS.md`。

## 功能点

| # | 功能点 | 判据（可机检） |
|---|---|---|
| D7 | 设置与凭据 | provider 增删、key 管理、preset / custom 三协议、agent 参数面板、i18n（en / zh） |
| D8 | 记忆与检索 | memory / code_search / doc_search 与索引状态（**复用核**；属 agent 工具面，非 UI 搜索框） |
| D9 | MCP | 服务器增删与工具入口（复用核） |
| D11 | 首启向导 | 无终端完成：**两路**——① 本地配置：选 preset → 填 key → 校验通过即可对话；② **登录团队服务器**（地址 + 账号 + 密码 ⇒ 登录成即用——模型面由 server 派生，免自配 provider；能力单源 = server 侧 AC-31）。两路互不阻塞：失败 ⇒ 就地出原因（四句逐字沿用 B1）并可改选他路；**首启配置三保真（用户裁定——四项全做）**：① **点得着**——唯一写盘钮显著可辨（不靠猜；控件族计数随动）∥ ② **存得下**——主路径（含步 1「下一步」）不得静默丢已填 key ∥ ③ **不退空**——仍未配置时「完成」不得静默退场（提示/拦住）；验收含真 Electron 使用面用例（沿 D16 定规）∥ ④ **校验看得见**——向导步 1「校验」结果须就地可见（用户裁「校验也修」；现读 = `settings.verify` 切片在向导树零消费） |
| D16 | 首启空态引导 | 新装首启（无项目 / 无会话）⇒ 对话流区给**可操作引导**（动作控件在场 ⟺ 句柄在场 · 零假按钮），不得止于「无出路的界面」；**no-session 态到达路径 = 首启 ∕ 全新配置**（运行期 UI 不要求零会话驱动路——用户裁 = A）；**凡改桌面可见面 ⇒ 验收须含一条真 Electron 使用面用例**（先例 = `T-DSK32`；**测试文件随修随加——不进设计面条目**（用户裁定），验收由父侧真跑闭合） |
| D37 | 设置面样式对齐 VSC | 桌面设置面**样式对 VSC 端对齐**——用户「我希望至少跟 vsc 端样式上对齐」；锚样本 = 渠道段实拍对比（VSC = **两行卡列**〔行1：`● 名 ★` + 右对齐 `Key ∥ −`；行2：`模型 · URL` + 右对齐 `proxy` 开关；卡界分明 ∥ 断行恒定〕）；收正范围 = 设置面全七段（渠道 = 锚点首段，余段同语言同收）——**功能面不删**（校验 ∥ 修改 ∥ 移除等桌面既有动作保留，只收形/位/密度）；信息架构（七段）∥ 布局面（居中列——实证正确）零动 |
| D39 | 设置弹窗化（菜单子菜单 ⇒ 应用内模态 · 升级版设置面） | **A 案 = 应用内模态弹窗**（用户裁「先按照a做吧」）：设置菜单内**多子菜单**（分组基线 = 现有七段 + 维护 + 关于与快捷键——细目设计定；**菜单组项 = 六——「模型」不入菜单**（段名 = 「模型」——用户裁）〔模型选择归输入面板——用户裁；设置页面七段零动〕），每子菜单项 ⇒ 打开对应配置组的**应用内模态弹窗**（七段读写/确认/失败链复用）；**现有设置页保留**（升级件并存——验收 OK 后再议撤）；边界 = 本轮**不做**独立设置窗口（B 案）∥ 不删现有页 ∥ 七段值面语义不改 |
