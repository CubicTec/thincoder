# 桌面端（DESKTOP）· 需求

> 板块 = **桌面端产品定性**——ThinCoder 第三个接入端的定位、功能范围与边界。
> 本档 = 桌面端产品级定性的需求层权威；产品族定性（三端关系）与跨产品共享契约见 `docs/core/requirements/PROJECT.md`（§1 / §3）。
> 核机制面（agent 主循环 / 工具 / 记忆 / 配置）**只住核**，本档不重述（单一权威源）。

## 1. 模块目标

给不想、不能用 VS Code 的人一个**独立桌面入口**：同一个 agent、同一份配置与会话、比终端更宽的会话与活动视图——单项目多会话，没有终端也能配好并开始干活。

## 2. 定位

| 项 | 内容 |
|---|---|
| 品类 | 通用 AI 编码智能体的**第三个接入端**（形态 = 桌面应用）——不改品类定性（`docs/core/requirements/PROJECT.md` §5.1） |
| 目标用户 | ① 不装 VS Code 的开发者；② 需要比 TUI 更宽的会话 / 活动 / 后台视图的人；③ 不熟命令行的使用者（首启无终端可完成配置） |
| 与另两端 | 同级独立产品、互不依赖；读写同一份 `~/.thincoder/config.json` 与 `~/.thincoder/sessions/`（承 `docs/core/requirements/PROJECT.md` §3 的 C1 / C2 契约） |
| 项目模型 | **单项目**：一次服务一个工作目录（会话按 cwd 寻址）；多项目并行 = 开多个实例（核已有跨实例协作面） |
| 宿主 | Electron——桌面运行时按**宿主平台**口径（与扩展端把 VS Code API 当宿主同支）；Electron 随发行物分发，其体积 / 供应链 / 三平台打包链成本落本端发行面 |
| 前端 | **零框架手写，纯 DOM + 浏览器原生**；**与扩展端共用宿主无关渲染核**（用户裁定——核落点 / 边界 = 设计轮定形） |
| 壳装配 | 核单源（`thincoder-core/agent/assemble.mjs`——三端对位收编）+ 本端 adapter（cwd ∕ `_slot` ∕ 校验调用） |

## 3. 界面形态

> 控件 / 样式 / 断点等细部留给设计轮。

### 3.1 主界面 = 会话面板（单面板 · VSC 模型）

**会话模型裁定**：多会话标签模型**裁撤**——会话面 ⇒ **VSC 单面板模型**（会话切换 ∕ 新建 ∕ 列表按 VSC 会话面逐元素移植，不新造）；标签条 ∕ 标签存储 ∕ 关闭确认 ∕ 页随动 ∕ 每键一槽（`session:<n>`）**随之下线**。
**左列裁撤（续裁「整个左侧栏都废掉」）**：会话切换 = **VSC 同款下拉选会话**（原左侧会话列表 ∕ 新建入口并此）；**整个左侧栏（会话列表 ∕ 项目目录 ∕ 项目级信息）随裁废**——VSC 无对位面不新造。
本节含「标签」·「左列」各句以本条为准。

```
┌────────────────────────────────────────────┬────────────────────┐
│ 会话面板（单面板 · VSC 模型）                 │ 本会话活动池        │
│ 会话控制：下拉选会话 + 新建（VSC 形）          │  ▸ 子代理块（角色 · 模型│
│ 输入区：模型 / 推理档位（控件行就地可改）      │    + 状态）        │
│ 对话流：流式 token · 推理块 · 工具卡          │  ▸ advisor/consult │
│ 审批卡（流内）· 错误卡                        │  ▸ 队列            │
│ 输入框（Enter 发送 / Shift+Enter）           │  ▸ 待审批（计数 +  │
│                                            │    操作区）        │
│                                            │ 随活动会话 · 可折叠 │
└────────────────────────────────────────────┴────────────────────┘
状态栏：模式四（AUTO / PLAN / ADVISOR / ENG · 真态时）行首 · 上下文占用（活动会话） · 跨会话待审批提示
```

- **会话控制（面板内 · VSC 形）**：下拉选会话（**全部**会话 = 历史，运行中 / 待审批带位标；与 CLI / 扩展端是**同一份**——共享会话目录，点开即续）+ 新建入口；左列裁撤后无第二入口。
- **会话面板（单面板 · VSC 模型）**：对话流 + **右侧本会话活动池**（两栏并列；池可折叠——折叠后对话流得全宽）。
- **输入区（面板内底行）**：**三值（provider / 模型 / 推理档位）唯一居所 = 控件行**（模型钮（两级：渠道 → 模型）· 推理钮）——**会话级可改**（随会话槽持久化，切会话即随之切换，与 CLI / 扩展端同一份槽；**推理档位槽字段 = `effort`**——核侧已落，判据单源 = `docs/core/design/SESSION.md` §6.21 ✓）（用户裁：会话头面退场）。
  **模式四位（AUTO / PLAN / ADVISOR / ENG）住状态行行首**（与 CLI 同段位——「屏面为准」重审裁定；槽字段 = `autoApprove` / `planMode` / `advisor.guard` / `engineering`——真态时在场）。
  注意区分：**工程模式状态**是会话级（住会话槽），但它 **ON 方向的准入判据**要读项目根的 manifest 档——两者不同层，不得混为一谈。
- 会话控制住面板内（下拉 + 新建——VSC 形；第二入口不存在）。
- **对话流**：消息流（流式 token · 推理块）· 工具卡（名称 + 参数摘要 + 状态 + 可展开结果，**含改动摘要** = 文件 + 增删行数；**diff 预览按对齐办**——VSC 同款行级 diff）· 错误卡 · 审批卡（流内嵌）· 输入框。
- **活动池（每会话一份 · 会话视图内靠右）**：子代理活动块（粒度 = 角色 · 模型 · 用时 · 回合 + 状态词；**内容回显 = 核件 tail-3 / 展开**）· advisor / consult · 队列 · 待审批（计数 + 操作区）。**位置与「全局右栏」同形，差别只在归属**：每会话一份、随活动会话切换（全局常驻池不存在——见 §3.4）。
- **状态栏**：**模式四位行首在场（真态时）** · 活动会话的上下文占用（实时读数）· **跨会话告警**（他会话待审批 ∕ 运行——不静默等待）· **团队登录态常显**（用户提——原话「主界面上看不见能行吗？」⇒ 不行：**已登录** ⇒ 状态栏可见**成员 + 服务器**（形随设计轮）；**未登录** ⇒ 不占位（或入口提示——设计轮定）；三端同批）。
  **同一事实只出现一处**：三值配置项住输入区控件行、模式四位住状态行行首（两处各有其位，不得重复呈现）；团队卡 = 设置面**管理面**（label ∥ 详情；**轮换 = 已落**——管理面就地动作，服务端 `POST /api/client/rotate`），状态栏 = **常显摘要面 + 直达入口**（**点击 ⇒ 就地登/退**——用户裁定：登/退不得要求先钻设置；两处不互抄。）。

### 3.2 一回合的时序（可感行为）

1. 用户发送 ⇒ 对话流流式推进，本会话活动池出现活动块；
2. 需要用户点头时：**对话流内嵌审批卡** + **本会话活动池的待审批计数 +1** + **告警位显形**；若你在别处，**状态栏给提示**（不静默等待）；
3. 子代理在活动池活动（粒度 = 角色 · 模型 · 用时 · 回合 + 状态词；**内容回显 = 核件 tail-3 / 展开**）· 完成后**归档入流**（D3 / D20）；**并发可见性 = 不翻页可见谁在跑 ∕ 谁在等**；
4. 回合收尾：结果进对话流，状态栏上下文占用更新。

### 3.3 首启（无终端可完成）

选 provider → 填 key（真调一次校验）→ 选工作目录 → 可用。
若 `~/.thincoder/config.json` 已存在（CLI 或扩展端已配）⇒ **跳过向导**，直接进主界面。

### 3.4 不出现在界面上的

 文件树 · 编辑器 · 内置 diff · 终端面板 · 常驻多项目面板 · **常驻全局活动栏**（活动池随会话——§3.1）——均无；前两项 = 暂缓项；内置 diff / 终端面板 / 常驻多项目面板 = §5.2 边界；常驻全局活动栏 = 形态裁定。

### 3.5 待设计形（本轮不锁）

- 同项目多会话**并行跑**时，活动池的池 / 队列分层显示形态；
- 跨会话告警位的精确形；
- 会话行**标注来源端**（该会话由 CLI / 扩展端 / 桌面端所建）——核侧「**创建端**」字段**已落地**（`listSlots[].createdBy`）；字段缺失（老槽）时**退化为不标注**（**不猜测**——「当前占用端」与「创建端」不同义，不得冒充）。

**现状定性**：**本节四项已全部落地**（as-of 2026-10-15 实测）—— 逐项见下；需求出处 = §3.1 / §3.2 与 §4（D2 / D3 / D6）。

### 3.6 两端对齐重定位（用户走查三点 · 待勘察定形）

**缘起** ✓：用户真机走查——原文三点：

1. 「UI 跟 CLI 和 VSC 的差别都太大，我希望有与 cli 基本对齐的状态行，希望会话面板与 vsc 基本对齐」；
2. 「把工具操作显示在右边列意义不大，我认为那里应该用于显示各类子agent，替代vsc端的live面板」；
3. 「会话流显示界面我看着也不舒服，我觉得应该跟 VSC 对齐」。

**方向口径（待勘察后逐项定形）**：

- ① **状态行 ⇒ 与 CLI 基本对齐**（读数 / 字段 / 呈现面）；**会话面板 ⇒ 与 VSC 基本对齐**；
- ② **右列（活动池）语义重定位**：工具操作面 ⇒ **各类子 agent 面**（承担 VSC live 面板角色）；
- ③ **对话流呈现 ⇒ 与 VSC 对齐**。

**勘察面**（勘察报告落设计档）：CLI 状态行（现物字段与布局）· VSC 会话面板与对话流（呈现机制）· VSC live 面板（内容 / 数据源 / 时机）· 桌面现状对照——逐项差值 ⇒ 设计轮定形。

**约束** ✓：§2「同级独立产品、互不依赖」不变；**共用口径已改判**——前端共用**宿主无关渲染核**（两端各自适配宿主胶水；核落点 / 边界 = 设计轮定形）——「基本对齐」由同核不同壳**结构性成立**。

**对齐口径（用户裁定）** ✓：

- **「对齐」= 长得像 + 行为一致（观感与行为两端基本一致）**——凡以「对齐」为名的面，交付标准即此（用户三重强调）；
- 核 = **手段**（机制单源 + 两端**消费同一核件** + 值对齐）；核设计档「语义对齐 · 非像素」**不构成交付豁免**；
- 原话：「我他妈的就是要你做成长得像，你才建议我做公共核的」——公共核上马即为对齐服务；
- 落点 = 核件接入（`renderSubBlock` / `activity-view` 族）+ 值对齐。

**勘察已落**——四物对照在册：CLI 状态行 15 段（纯函数段可复用）；VSC live 面板 = **子 agent 实例带**（`thincoder-vscode/src/extension/panel-subagent-relay.mjs`——位置非右栏，桌面为**角色**对位）。
  桌面 relay 事件**宿主已解析、渲染面丢弃**（`agent-bridge.mjs:15-27` × `renderer/events.mjs:220-221`）；VSC webview 宿主胶水分布（`state.js:10` 单源 + 交互模块散布；CSS 变量经 `base.css:8-20` 映射层）。

**功能面全量对位** ✓：VSC 端**已有的一切用户可见功能**（命令 ∕ 视图 ∕ 面板 ∕ 自动行为 ∕ 会话 ∕ 模型 ∕ 索引 ∕ skills ∕ 多实例等）⇒ 桌面**必须有**——复用 ∕ 上提默认；**缺项 = 缺陷**（真端差须实证，沿本节「对齐口径」）；**全量清点 + 缺项一次补齐**（清点 = 双路侦察：VSC 功能注册表自上而下 ∕ 核件能力三端消费自下而上；回件后归批）。原话：「功能上，你也好好查查，我不想再出现什么 vsc 端有的功能 desktop 没实现的。——一次处理」。

**验收（机检）**：① **清点完备**——双路侦察融合缺项表在册，**逐项**终态 ∈ {已落定 ∕ 判定在册（非用户可见 ∕ 归先落者）∕ 真端差登记三件齐}——**未处置悬项 = 0**；② **走查**——真机走查表逐项通过；③ **集成测试**——core ∕ cli ∕ vsc ∕ desktop 四集成测试全绿。

## 5. 边界

### 5.1 暂缓（本轮不做）

- **文件视图与编辑器**（编辑 / 保存 / 内置 diff 编辑器本体）；**「打开文件」已出暂缓**——文件链接点开按对齐办；
- **常驻多项目面板 / 项目切换器**——多项目并行以多实例满足。

### 5.2 不做

- 云服务 / 托管平台、模型 / 推理服务、工作流引擎；
- 复制核机制（机制只住核）；另立会话 / 配置存储格式（照既有契约）；

## 6. 非功能

| 项 | 要求 |
|---|---|
| 平台 | **Windows / macOS / Linux = 目标平台**（设计面三平台无偏：契约 ∥ 路径 ∥ 宿主面）；**交付分期（2026-10-01 D32 阶段令）= 阶段一 Windows 产物；macOS ∥ Linux 产物随阶段二（构建机后补）** |

| 依赖 | 零第三方运行期依赖——前端零框架手写；宿主 = Electron（宿主平台口径） |
| 性能 | 启动可接受、长会话渲染不退化——**阈值与测法**：每 chunk 更新成本对文本长度**近似平坦（O(1)）**——单块 80KB ≤0.3ms/chunk · **帧 p95 ≤16ms@80KB（60fps 用例；密文 md 帧 p95 ≈31ms）** · 平坦比（80KB ∕ 10KB）≤2×；测法 = 真机计时用例 + 平 node 用例 |
| 凭据 | key 明文落 `~/.thincoder/config.json`（承 `docs/core/requirements/PROJECT.md` §3 的 C8） |
| 国际化 | 承产品定性（英文为默认面，含 zh） |
