## 1. 总体定位

上下文压缩 · 标题 · 文本额度 = 上下文压缩（现体 `thincoder-core/context.mjs`）**+** 会话标题**+** 文本额度（VSC `agent/run-helpers.mjs` 的 `safeSliceUTF16` 族）。

## 2. 功能性需求

### 2.1 本子系统条目

- **【派生 · 非用户原话】** 上下文压缩 / 会话标题 / 文本额度归一为**核内单一纯函数面**（压缩触发 · 摘要 · 降级截断 · 尾部预算；计长口径 = UTF-16 码元）；会话标题的格式分派（CLI 仅 OpenAI 兼容 / VSC 三格式）按**端差注入**。
  源 = 设计档 `CONTEXT-COMPACTION.md` §2.1 #162–#164。

- **【派生 · 非用户原话】** **恢复面回声安全**：已落盘会话的机读线在**恢复路径读取时**归并回声病态形态（「无 `reasoning_content` 的 assistant 紧邻 assistant」——前条并入后条）；恢复后首个请求不携带该形态；**不推用户**（静默归并）、**不改会话档**（人读线 / 双线约定不变）。
  判定句：夹具 = 含病态对的落盘机读线 ⇒ 恢复后 `agent.history` 该形态计数 = **0**，文本拼接逐字守恒 + `tool_calls` 总数守恒，干净输入返回**同一数组引用**（零回归）；两端（CLI / VSC）各 ≥1 用例。源 = 设计档 `CONTEXT-COMPACTION.md` §6.10 #8 / D-CC19。

- **【派生 · 非用户原话】** **压缩调用复用会话前缀**：压缩请求 = 会话前缀（system + 中段真身消息——不截断、不序列化、**随带与回合请求同声明面的 `tools`**（**不随 `tool_choice`**——实施轮实测：该参数致服务端**丢弃 tools 区**（token 证据：prompt 与无 tools 形态同值）⇒ 按设计预注册判定规则 §6.14 采纳**备选②**；命中面按
 `tools` 声明分区——同前缀带 tools **84–98%** vs 去 tools **0%**）；**并随带与回合请求同源的 `reasoningEffort`**（实测：同值 ⇒ 生产口径首现命中 **92.86% / 93.65%**（两次独立运行）vs 异值 **0%**；不硬编码 · 无配置 ⇒ 缺省）+ 尾部指令一条；不再以「全新 user 消息 + 序列化正文」形态发送。
  判定句：同会话回合调用命中率 ≥90% 时，compress 轨迹 `cached / prompt ≥ 0.9`；**选中面**一致（仍只喂中段），**表示面**改变（真身消息、不截断——保真度预期↑）；切点须为配对安全边界。源 = 设计档 `CONTEXT-COMPACTION.md` §6.14 / D-CC20。

- **【用户需求】** **模型主动整理上下文（`context` 工具 · 操作区分）**：
  - **F-CC1 感知**：模型可查当前上下文的**用量与构成**（总量 / 距压缩阈值 / 各段占比）——「该压了吗」要有数（现态 = 模型看不见自己的占用 ✓）。
  - **F-CC2 主动压缩（携要求）**：模型在**它判定的时点**（工作方向转换 / 自认上下文嘈杂）携 **focus 要求**发起压缩；机制**自动附上**当前任务 / 目标面（task · goal），使摘要在取舍上对齐将要做的工作；实现**走既有压缩机器**（安全点 / 摘要链 / 压缩面板 / 失败可见面全复用 ✗ 不另起）；**回执须露可回查锚**（全史所在（当前会话文件路径）与取回路径——使「压掉的可取回」**一步可行动**）。
  - **F-CC3 噪声清理**：模型可丢弃**陈旧的工具输出**——与压缩**语义正交**（删 vs 摘要）；记录面不死（见边界）。
  - **F-CC4 方向转换轻推**：任务 / 目标面变化后，在上下文落**一行提示**（「可考虑压缩 ✗ 当前目标 = X」）——**提示非命令** ✗ 压缩决策恒在模型。
  - **F-CC5 工具形态**：上述能力收为**单一 `context` 工具，以操作区分**（感知 / 清理 / 压缩三操作）——工具表 +1 项，双端（CLI / VSC）一致；工具说明 = 运行时可见面（教模型写「下一步要什么」）。
  - **判定句**：① 携两条**相斥 focus** 各压一次 ⇒ 两份摘要的取舍方向**可断言**（聚焦词命中计数差额）；② 压缩后 `read_history` / 人读线**全量不变**（记录面不死）；③ 清理后活上下文占用下降 ∧ 记录面不变；④ 方向转换后提示行**恰一次**（去重）∧ 零调用时零副作用；⑤ 双端工具表各 +1 项（`context`）× 三操作可达。
  - **边界（不做）**：阈值自动压缩**保留为兜底**（语义不动 ✗ 双轨并存）；**记录面不死**（机器线之外全量不变——承 §4.2 F3 口径）；**不做自动方向检测**（轻推 = 一线提示 ✗ 不得自动压）；**不新增用户侧命令**（`/compact` 类 ✗ 本期未要求）；**子代理面** = 设计轮裁定（**须带可回查性论证**：子代理现无 `read_history` 通道 ✗ 若给则同轮论证可达性，否则明确登记为边界）。

- **【用户需求】压缩线目标 = 窗口 75–80%**（用户 2026-10-16 裁定「压缩线 ≈ 窗口 ~70–80%」——症状 = agent 以上下文快满为由自行停工 ✗：报面主百分比用触发线作分母 + 阈值链双重保守 ⇒ 实际在窗口 ~37% 就触发 ✗）：
  - **阈值链**：显式 `config.agent.compactThreshold` 优先；auto = 可用窗口与 `⌊窗口 × 0.8⌋` 取小，可用窗口 = 窗口 − 完成预留（预留 = `min(显式 maxTokens 否则规格 maxOutput, ⌊窗口 × 0.25⌋)`）——阈值落窗口 **75–80%**（`resolveCompactThreshold` 单源）。
  - **报面**：主口径 = **窗口占用**（`total / window`）；压缩线以**具名数值**露出（不再作百分比分母）；同名输出不得两个无名百分比并存。
  - **判定句**：① 逐档推算全表（`model-specs.mjs` 全量）新占比 ∈ **[75.0%, 80.0%]**，两式（预留未封顶 / 封顶）与定式互推一致；② stats 首行恰含一个具名百分比（分母 = 窗口）∧ 压缩线以具名数值在场；③ 溢出风险论证三件在场（真溢出后果 ∥ 兜底接法 ∥ 高风险档清单）。
  - 源 = 设计档 `CONTEXT-COMPACTION.md` §6.2 ∥ §6.16.4 ∥ D-CC29–D-CC30。

## 4. 需求条目

### 4.1 压缩体验——F1–F4

- **F1**：压缩**开始**时立即提示（用户马上知道「在压缩，不是卡死」）。
- **F2**：压缩执行中在 TUI 显示**进行中状态**，完成后显示结果（摘要长度 / 耗时 / 成功或失败）。
- **F3**：压缩失败不再静默——错误文本可见（UI 行 + console.error），诊断可追踪。
- **F4**：非 TUI 环境（headless / VS Code 桥）不崩不阻塞——回调缺省安全。

### 4.2 探索结果语义摘要——F1–F3 · N1–N3

> **需求（用户报告「主 agent 历史质量差」）**：机器线历史（`history`）在压缩阈值触发前就因内联探索逐步结果而膨胀；即便触发压缩，LLM 摘要也可能丢关键信号。在**每轮 runAgent 最终返回时**把本轮写入机器线的探索类结果蒸馏为语义摘要、并强化压缩保真，使机器线在任意时刻信号密集、可恢复。

- **F1**：当一轮内连续 / 成批的探索类工具结果写入机器线后，在轮末被 LLM 蒸馏为语义摘要（发现了什么、在哪、关键结论），而非裸堆结果或机械截断。
- **F2**：压缩摘要（SUMMARIZE_PROMPT）在压缩时，除「已完成 vs 进行中」外，显式新增保留：已改动文件清单、未决点 / 待办。
- **F3**：人读线 `_fullHistory`（落盘 `fullHistory`）保持全量不变；机器线 `history`（落盘 `contextHistory`）承载摘要后的信号密集形式。（**记录 / 落盘语义**——完整记录在盘、压缩不触；运行期内存表示为有界窗口，机制见 `docs/core/design/SESSION.md` §6.14。）
- **N1**：摘要质量优先，token 成本不作决策变量；摘要调用必须 `thinking:null` 且不接 onToken / onReasoning。
- **N2**：压缩机制落地单一权威面：压缩面**单源**（`thincoder-core/context.mjs`）；一致性由单源承接。
- **N3**：轮末摘要失败不得阻塞 / 影响 runAgent 返回（静默跳过，原始历史保留）。
