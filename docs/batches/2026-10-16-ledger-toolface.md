**出口面的取舍与代价（如实 · 逐条）**：

1. **够硬吗——判**：**「清单挂在开局自查 / 收口的纪律上」这一起手式不够硬**。依据（一手）：`docs/core/design/prompts/persona-engineering.md:87` / `:88` 两条纪律**在册**，而**池子只进不出的实测结果**（本会话待讨论 ≈44 行、其中 ≈20 行 `trigger=归批` 而批名只在散文）证明纪律面不生效；且本会话为**恢复会话**，主 agent 漏了开局自查而机器面零提醒 ⇒ **纪律在册、机制为零**。⇒ 本设计把该起手式的**读数**机械落面（不靠谁去调一条自查命令）。
2. **既有输出契约变更**（代价①）：L2 括号位由 `（老化 <aged>）` 扩为 `（老化 <aged> · 待处置 <overdue>）` ⇒ 逐字契约变更，受影响面 = `formatDetailLine` 单源 + 三端逐字断言（§7.2 / §7.3.1 既有断言）；`warn` 聚合口径由 `aged>0` 扩为 `overdue>0`；`buildScan` 形状增 `overdue` 键。**为什么值** = 状态槽首扫**零模型动作**，是唯一不靠模型动作的必然可见面（只在 `count` 加桶仍要有人调 `count`）。
3. **谁消费该读数**（代价②）：`ledgerCount` 出参改 `{ count, overdue, evidenceOversize }` ⇒ 消费面 = 收口行 ∥ 显示面 marker（`.count` / `.overdue` 零重算）∥ ACP read-data（`thincoder-cli/src/acp/read-data.mjs:76`）——三者同源。
4. **30 天阈值**（代价③）：**不可配** —— `AGING_DAYS` 常量单源（`ledger-db.mjs:62`）；可配会把「同一数在不同端 / 不同人处不一致」带进来，且用户 2026-10-15 已裁「无限机检反感」（可配 = 更多旋钮）。要改 ⇒ 单点改常量（另轮）。
5. **不自动改行**（代价④）：机判只产读数与清单；**唯一机器写 = §6.2 收口重锚（事实句）**——`status` 不静默降级、`认账不排期` 不机器代填（政策判断归行主人）。「自动降级」在本设计里的落形 = **降为读数桶 + 挂进必然读到的清单**。
6. **残缺**（代价⑤）：会话收尾无机器事件 ⇒ 会话中途攒下的行只在**下一次开局**被扫（滞后一个会话）；`resume_when` 锚可选 ⇒ 存量散句条件不产生 `resume_due`。
