# Function Spec · 提示词落地面（代码单源）

> 模块划分权威源 = `docs/core/design/ENGINEERING-MODE-V2.md` §2.2（M9）

## ① 模块目标

提示词 = **代码单源**：唯一副本 = `thincoder-core/prompts/`（产品代码面）；规则本体 = 中文机制文档。提示词修改**先改机制文档**，再由 **coder** 改 `thincoder-core/prompts/` 对应档——不是 cp、不是照抄。

## ② 功能点

1. **更新流程**：先改机制文档（规则本体）→ 再由 coder 改 `thincoder-core/prompts/` 对应档（`promptsLanding`）。
2. **落点读声明面**：模板 = `docRoot.design` + `/prompts` 推导；落地 = manifest 顶层平级键 `promptsLanding`（落地是代码仓路径、不入 docRoot 文档体系）。
3. **提示词内不得要求「列候选对比」**。
4. **兑底 = 收口核对清单（非机检门 · 用户裁定）**：机制档改动后，收口时**人工核对四项**——① 提示词已同步（新增 / 删除 / 改写逐档）② 提示词档集合 = `thincoder-core/prompts/`（16 档，单副本）③ 核包提示词测试全绿（`node --test` 于核目录）④ 收口记录一行（「机制档 → 提示词 已同步」）。**不挂机检**（同上裁定）；**未裁项** = 是否另加机检（保持不挂，除另行裁定）。

## ③ 边界（不做什么）

- 不做提示词**内容权**（提示词内容 = 主 agent 内容权 + coder 落笔）。
- 不做需求档 / 设计档。
