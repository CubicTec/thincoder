### §2.6 判据口径判定表（**可证伪——逐条**）

**计落笔**（⇒ 该回合「有产出」）：① `FILE_MUTATORS` 六件（`write` / `edit` / `insert_after` / `apply_patch` / `delete` / `hashline_edit`）任一**执行成功**；② **同一文件重复编辑亦计**（每次执行 = 写序 +1）；③ 一次调用触多档（`apply_patch`）= 仍计 1 次事件；④ 中断批内**已执行成功**的写。

**不计落笔**：⑤ 只读工具族（`read` / `grep` / `glob` / `ls` / `tree` / `repo_outline` / `code_search` / `doc_search` 等）；⑥ `git`（含写型子命令）；⑦ `bash`；⑧ **`batch` 追加（§2 段写）**；⑨ **`file_ops`（移动 / 复制 / 改名）**；⑩ 写工具**执行失败**（结果 `Error:` 前缀）。

**不判**：⑪ `_mutationSeq` 非整数（未跟踪执行面）⇒ 记「有落笔」（零动作、零误报）。

**⑧ / ⑨ 裁定理由（四条）**：① 目的面（口径对象 = 工作区**产出**）；② `batch` 若计入 ⇒ **判据随端而异**（核内记账缺省 no-op（`batch.mjs:57-62`），VSC 端注入 `_touchedFiles`（`thincoder-vscode/src/agent/setup-tooltable.mjs:29-33`））= 端间分叉（缺陷）——改判据后 `_touchedFiles` 退出判据 ⇒ **该分叉自动消解**；③ `file_ops` 在 `FILE_MUTATORS` 之外（含它的 `PEER_WRITE_TOOLS`（`peer-domains.mjs:42`）= L3 冲突 / 足迹面谓词，非「代码变更」谓词）；并入需第二谓词（同事实两套知识）或放大共享 `FILE_MUTATORS`（连带改权限门 / 变更失效链语义——越射程）；④ 成本面——误报廉价（只推提醒）、漏报才机制空转。**解消窗**：真出现只经 `batch` / `file_ops` 的原地长跑 ⇒ 按实况再议。
