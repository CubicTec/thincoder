## 4. 需求条目

### 4.1 总体需求（为什么）

**问题循环**：用户实测问题（「4 个 explore 完成但主会话回合直接结束无消化」）暴露——每次诊断都靠**临时插桩再删**，
成本高、覆盖窄、撤后无痕。用户裁定：**常驻诊断事件日志**——保留一天——问题发生时直接查日志定位断点——根治插桩循环。

### 4.2 机制约束（功能性——架构级表述）

- **F-L1 事件骨架日志**：回合 / 工具 / 子代理 / LLM 调用的关键事件序列（时间戳 + 事件 + 关键参数 + 耗时）。
- **F-L2 B 级摘要**（用户裁定）：LLM 响应头（≤ 300 字符——非错误异常响应可见：空回复 / 超短 / 格式错）、工具结果头（≤ 200）、错误消息（≤ 200）——落本地 `~/.thincoder/logs`。
- **F-L3 按天轮转 + 自动清理**：`agent-YYYY-MM-DD.log`——**每进程每日首次写事件时机会式删除超龄日志**（非仅启动时——extension host 可长驻）——用户零手动维护。
- **F-L4 覆盖范围**：主回合骨架 · LLM 调用（无内容）· 工具调用（无参数值——敏感参数永不落）· 子代理（含 async settle / digest 轮）· 挂起态。
- **F-L5 零侵入**：日志写入是 fire-and-forget（失败静默——绝不影响主流程）。
- **F-L6 两端一致**：CLI + VS Code 同事件面（共享目录、同格式）。
- **F-L7 性能**：每事件一次小 append（< 1KB）；正常回合事件数 < 1000——无热点。

### 4.3 非功能性（硬指标）

- **NF-L1**：日志写失败（磁盘满 / 权限）**静默降级**——主流程零影响（进程内首次失败置死，当日不再尝试）。
- **NF-L2**：单事件行 < 512 字符（超长截断）；错误消息 200 截断。
- **NF-L3 敏感字段零落盘**：字段名精确黑名单（`apiKey` / `designToken` / `password` / `secret` / `token`，大小写不敏感 + 防御性 `authorization` / `proxy` / `proxyUri`）+ 内容只扫密钥形态——工具不记 args——URL 不入事件。
- **NF-L4**：保留窗口最近 1 天（以文件名日期当日结束为龄基准——今天+昨天保留）。
