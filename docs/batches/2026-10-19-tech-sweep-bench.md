### `#1652` runner 末行自相矛盾（需裁 → 本节裁定）

- 现状（`bench/check/run.mjs` 实读）：`:97-98` 超时/崩溃/缺汇总行 ⇒ 记入 `failedFiles`；`:105-108` 有失败档 ⇒ stderr 一行 + `exitCode = 1`；`:110` 末行只打 `bench/check: ${P} passed, ${F} failed` ⇒ 整档崩溃时可得「`0 passed, 0 failed` + exit 1」。
- **裁定 = 末行并入档级计数（条件式追加）**：末行改为
  `` `bench/check: ${totalPassed} passed, ${totalFailed} failed` `` + （仅当 `failedFiles.length > 0` 时追加）`` `, ${failedFiles.length} failed file(s)` ``。
- 选它的理由（对二分法另一支「加独立 `failed_files=N` 行」）：
  ① **矛盾点就在末行**——tail 读的人只看末行，另起一行等于把证据放在读者不看的位置（现有 `失败档：` 行在 stderr 已存在，仍被读成「0 failed + exit 1」，即证）；
  ② **条件式保住绿时输出逐字不变**——`MODEL-BENCH.md:692` 的「汇总行恒为 `bench/check: N passed, M failed`」与在册读数（`#1655`：117 passed / 0 failed）继续成立，改动面 = 恰好那一种矛盾态；
  ③ 子进程契约不受影响：`:87` `summaryOf` 解析的是**各档子进程 stdout**，与 runner 自身末行无关（`harness.mjs:61` 那一行不动）。
