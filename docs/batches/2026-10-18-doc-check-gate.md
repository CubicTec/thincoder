## 一、四个待解问题的答案（含被否方案 + 理由）

### ① 「本轮改过的档」怎么判定
**答：两层，各用各自有证据的来源——**

- **子代理（交付当下）**：范围 = **本会话触达记账** `ctx.agent._touchedFiles`（`write` / `edit` / `insert_after` / `hashline_edit` / `apply_patch` / `delete` 六类写工具逐次记账——`agent/helpers.mjs:86` 的 `FILE_MUTATORS`；记账点 `agent/record-results.mjs:162-169` ∥ `agent/turn-loop.mjs:238-241`）∩ 声明域（`scanDirs` − `exclude`；2026-10-18 实读 = `docs` 域 212 档）∩ 盘上存在的 `.md`。
  `docs` 显式参数 = **补充通道**（未记账通道改的档：`bash` 改档 / `file_ops` 移档 / 跨会话）。
- **父侧 §6（权威面）**：范围 = 显式 `docs` = 本轮文档档集（未提交 `git diff` ∪ 本轮提交 diff）。子代理自报的范围是子集，**父侧以自查清单为准**。
  理由（实读）：`mergeChildMutations` 只并入 eng-coder（`agent-tools/subagent-async.mjs:350`），eng-designer 的触达不进父账 ⇒ 父侧不能拿子代理记账当范围。

**被否**：
1. 子代理自己 `git diff` —— 工具面实读无 git 工具（`agent/family-tools.mjs:185` / `:187` 两分支）；且子代理 cwd 未必是仓根。⚠ 但 `verify` 内部会 shell 调 git（`agent-tools/verify.mjs:118-123`）——那是**报告面**，没有结构化交接口，不能当范围载体。
2. 父侧 spawn 时传「预计改动清单」当唯一来源 —— 预计 ≠ 实际，超清单改的档会逃出检查（`file 域声明语义` 已有定论：声明 = 预期触碰面，非边界）。
3. 全仓扫描后过滤报告 —— 报告面 = 全仓 ⇒ 正是「范围跑偏」这个病。
4. 纯自述清单 —— 可漏、无人复核（与审计面同款隐患）。
**代价（如实）**：走未记账通道改的档只能靠 `docs` 显式带；漏了由父侧 §6 的 git 清单兜住。

### ② 「拒绝交付」怎么实现
**答**：`doc_check` 增 `mode`（缺省 `report`，行为逐字不变）+ `docs`（仅 gate）。`gate` 模式**首行固定 verdict**：`DOC-CHECK GATE: PASS` ∥ `DOC-CHECK GATE: REFUSED（命中 K 条）`——机器可判串。
强制面三处：**交付协议**（子代理不得带 REFUSED 报交付）· **父侧 §6 前置**（无 PASS ⇒ 不提交批准 / 不核销 / 不 close / 不改台账）· **父侧独立复跑**（子代理声明不构成证据）。
**退出码**：工具面无退出码（工具返回字符串）⇒ 按需求 **F4 的二择一取「明确 refuse」形**；AC-3 文字里的「退出码非零」按此落地（**上抛项 1**）。

**被否**：
1. 新工具 `doc_gate` —— 同引擎同判据，描述面翻倍（工具描述预算已 **1.253× 基线**，`PROMPT-SYSTEM.md` §6.11）。
2. 独立 CLI 给真退出码 —— 同一检查的第二个实现面（D2）。
3. 挂到 `batch` 的 §2/§5 写入前 —— F7 上抛时反而写不了交付记录，账丢（「无账之笔」反向违规）。
4. 挂到 `verify` —— verify 语言/框架无关 + 文档快路径（`agent-tools/verify.mjs:182-187`）；塞进项目化判据即破其设计。
5. completion guard 逐回合推回 —— 工程模式**明确排除**逐回合机械推回（`agent/completion.mjs:76-80`），走流程驱动门。

### ④ 与既有「非门禁」定位如何共存
**答：同一个引擎，两种问法。**
- `report` = 全域报告态，原句逐字有效（不阻断 / 不置退出码 / 不接 CI / 输出不得被读作拒执行的理由）。
- `gate` = 交付时点的**范围化裁定**——拒绝的是**一次交付**，不是用户指令；「用户令 > 机检」总则零改（用户明令放行 ⇒ 照办并写明命中项）。
- 工具本体仍**不阻断任何动作**：强制面住交付协议与 §6 前置。

**被否**：把 gate 做成全局闸 / CI（把「清账」卷进每次交付 = 范围跑偏）；把 `report` 改成门禁（破坏既有定位与既有用法）。

## 二、机制形态（工具面 ∥ 引擎面 ∥ 提示词面）
- **工具面** `thincoder-core/agent-tools/doc-check.mjs`：`mode` / `docs`；范围**候选**取自 `ctx.agent._touchedFiles`（工具层有 ctx）；`report` + 传 `docs` ⇒ **拒**（不静默忽略）。
- **引擎面** `thincoder-core/doc-check/*.mjs`：`runDocCheck(root, {docs, mode})`——`files` = 全域（**解析基线不缩**：裸名唯一索引仍按全域建），`checkFiles` = 范围档（被判集）；锚 / 行宽各自只遍历 `checkFiles`，节判定按需读**被引目标档**——**不做全仓正文扫描**。
- **裁定面**：首行 verdict；命中逐条 `档:行` + 类；空范围给 `PASS（0 档）` + 一行照实说明（不静默当通过）；`docs` 含域外档 / 已删档 ⇒ 跳过行（非命中，但可见）。
- **判据零变**：仍只有锚 + 行宽两条（§3.20 判据 ① ②，单源 = §3.18 / §3.20）；本批只加「何时强制 + 判谁」。

## 二、五个设计问题（逐条答案）

**1. 范围：写段时 `docs` 查什么？要不要含批档？**
① = 写者 `ctx.agent._touchedFiles` 的 `.md` ∩ 声明域（`scanDirs` − `exclude`）∩ 盘上存在——交给引擎 `resolveRange` 求交（范围单源），`docsSource="session"`（与工具面 gate 同源）。② = 父侧触达记账同式 ∪ git 面（`git diff --name-only HEAD` ∪ `git ls-files --others --exclude-standard`，滤 `.md`，域求交仍归引擎）；git 面不可得 ⇒ 只用触达账 + 回执明示「git 面不可得」（不静默）。
**批档自身不传入**：`anchors.exclude` 含 `batches`（`PROJECT-MANIFEST.json:35-43`）⇒ 引擎只会给「跳过域外」行 = **假检查**；载体不是判据对象；gate 继承声明面、不另立域。要检批档 = 改声明面（另事）。
空范围 ⇒ `PASS（0 档）` + 照实行 ⇒ **放行**（K6 不变：空范围不静默当通过，但也不假拒）。
**代价如实**：`<批起 sha>` 只有父侧掌握 ⇒ 轮中提交面工具看不见，由 ① ② 合围 + 父侧协议跑兜底（协议面仍是权威范围面）。

**2. 引擎版本校验：batch 内调 gate 走不走 `staleEngineFiles`？**
走，且**同源**——两函数与 `ENGINE_FILES` 由 `agent-tools/doc-check.mjs` 迁住新档 `doc-check/version.mjs`（工具面转口，导出面不变；`ENGINE_FILES` 五 → 六档，增 `version.mjs` 自身）。门在**进引擎前**判版本，stale ⇒ `ERROR` 串直接返回。
**`ERROR` 消费分野**：② fail-closed（拒收口）；① **放行 + 回执明示**——F9 只在 ② 点名 ERROR；子代理无法重启会话，卡死写账 = 无账之笔（「无账之笔」反向违规）；而 ② 会拒收口 ⇒ 轮次不会被当成已通过。代价写明：引擎在会话中途被改写后，本会话的 ① 只记账、不产检查。

**3. 设计评审写 §3 是否同受检？——不检（裁定）**
理由四条：① F9 只点名 §2 / §5；② 评审工具集零写工具（`advisor/loop.mjs:44-48` 只读六件 + 仅绑定 `batch`），触达账恒空 ⇒ 门恒 `PASS（0 档）`，纯形式；③ §3 是发现记录不是交付物；④ 若检，`ERROR` 会卡住评审记录落档（「失败 ⇒ 勿 close」的反向故障）。评审若真改过档 ⇒ 父侧 ② 的 git 面兜住。

**4. 既有拒因零回归：门是新增前置不是替换**
门位 = 既有校验**全部之后**、写盘**之前**（见「三」清单）；既有错误串逐字、判定顺序逐序不动；gate 拒串前缀 = `batch:`（新增错误面，与 `batch_segment:` 迁移面分开）。

**5. 性能：每次写段跑一次 gate**
实测（2026-10-18 · 新进程 · `runDocCheck` 直驱）：空范围 **22 ms** · 8 档 **128 ms** · 报告态全域 **1084 ms**（212 档）。写段一次一跑，**不设缓存**——缓存键（mtime 集）算错即静默放行，正是本机制要关闭的失效模式；128 ms 远低于一次模型回合。

### 三、#2 范围分离判据（逐字 = §3.20「② 的范围分域」）

- **② 的范围分域（按作者归属 · 不设豁免清单）**——两集分开判：
  - **本批笔域集** = 父侧触达记账（`_touchedFiles`，含 eng-coder 合并账）∪ 本轮提交 diff（`git diff --name-only <批起 sha> HEAD` 中域内 `.md`）。`<批起 sha>` = 本批开工前 HEAD（父侧记入批档 §1）；取不到基 ⇒ 只认触达账 + 回执明示「基 sha 未定」。
  - **他批在途集** = git 面（`git diff --name-only HEAD` ∪ `git ls-files --others --exclude-standard`，滤 `.md`，域求交归引擎）− 本批笔域集；git 面不可得 ⇒ 只用触达账 + 回执明示「git 面不可得」（不静默）。
  - **裁定**：首行 `REFUSED（命中 K 条）` 的 K = **命中 ∩ 本批笔域集** 的条数 ⇒ K ≥ 1 拒收口；命中 ⊆ 他批在途集 ⇒ **不阻收口**，另起固定行 `他批在途 b 档（非本批笔域 · 未计入 K · 请其作者在其批修复）：<档>:<行> …` 逐档列出。
  - **为什么这不是豁免清单**：分界按**作者归属**判（谁写的谁修），不按「逐个放过」；他批命中仍在报面逐档可见、仍要在其本批修掉，只是不由本批代偿。笔域纪律（不许改别人的档）与收口门在此不互锁——此前两者互锁 = **收口死锁**。
  - **代价如实**：子代理进程内写的档（如 eng-designer 的设计档）不进父侧触达账，若又未提交 ⇒ 归入他批在途集、不阻本批收口；兜底 = 该档在**写入时**已被 ①（写者触达账）判过，且报面逐档可见。
